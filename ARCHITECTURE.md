# Структура discordio

Проект использует ES modules на сервере и в браузере, CommonJS в основном процессе Electron. Сборка веб-клиента не нужна: Express раздаёт модули напрямую.

## Сервер

`server.js` — точка запуска: загружает `.env`, открывает порт, запускает сторож Funnel и обрабатывает завершение процесса.

- `src/application.js` собирает приложение и предоставляет `close()`. Создание приложения само по себе не открывает порт.
- `src/config.js` отвечает за настройки и пути относительно корня проекта.
- `src/storage.js` читает JSON-базу, создаёт начальную комнату и приглашение администратора, сохраняет данные через временный файл.
- `src/domain.js` содержит функции приглашений, профилей, нормализации и хеширования паролей.
- `src/auth/` — сессии и ограничение запросов.
- `src/http/` — маршруты авторизации, картинок и статических ресурсов.
- `src/realtime/index.js` — подключения, heartbeat, комнаты онлайн и восстановление WebSocket с досылкой сообщений.
- `src/realtime/messages.js` направляет сообщения обработчикам `lobby-commands.js`, `admin-commands.js` и `room-messages.js`.
- `src/services/` — STUN/TURN и сторож Tailscale Funnel.

Сервисы создаются для каждого экземпляра приложения; тестовые экземпляры используют собственную временную базу. HTTP-маршруты получают зависимости при регистрации, WebSocket-обработчики — при создании. Формат базы и сетевых сообщений сохранён.

## Веб-клиент

`public/js/app.js` — подключение обработчиков и запуск. Изменяемые данные подключения и интерфейса находятся в `core/state.js`. Коллекции участников и локальное состояние медиа также принадлежат этому модулю. Данные настроек и работа с localStorage находятся в `core/preferences.js`.

- `core/` — DOM, состояние, настройки, иконки и тексты.
- `connection/` — WebSocket, переподключение и WebRTC-соединения участников.
- `media/` — микрофон, камера, демонстрация и отображение видеопотоков.
- `chat/` — сообщения, загрузка картинок и просмотр вложений.
- `rooms/` — список комнат, профиль в боковой панели, вход и выход.
- `auth/`, `admin/`, `settings/` — соответствующие сценарии интерфейса.
- `ui/` — карточки участников, кнопки, звуки и уведомления.
- `desktop.js` — интерфейс выбора источника демонстрации через preload-мост.
- `audio.js`, `gate-worklet.js`, `voice.js` — обработка аудио и озвучка событий.
- `bootstrap.js` — начальная конфигурация и восстановление входа.

Модули функций загружаются до подключения обработчиков. Функции импортируются явно; обновления общих переменных идут через объект `state`, а не через запись в импортированные значения. Медиа и интерфейс пока связаны прямыми вызовами между функциональными модулями; это не отдельные независимые приложения.

## Electron

`desktop/main.js` собирает основной процесс и обрабатывает его жизненный цикл. `desktop/src/` содержит модули окна, разрешений, IPC, трея, конфигурации сервера, deep links и глобального push-to-talk. В `desktop/preload.js` остаётся ограниченный мост к renderer. Новая папка `src/` включена в правила electron-builder.

## Проверки

```sh
npm ci
npm run check
npm run format:check
```

Регрессионные тесты используют `node:test`. Серверные тесты работают с временными каталогами и локальными портами. Клиент загружается как настоящий граф ES modules в jsdom; аудиогейт проверяется в отдельном VM-контексте. Electron-модули проверяются с имитацией системных API. Флаг `--experimental-vm-modules` нужен только тестовому загрузчику браузерных модулей.

Для проверки в установленном Electron:

```sh
npm --prefix desktop ci
npm run test:electron
```

Открываются два скрытых окна с отдельными сессиями и временной базой. Проверяются настоящее WebRTC-соединение, RNNoise, камера, демонстрация на искусственном видеопотоке, чат, mute, настройки и выход. Микрофон, камера и экран пользователя не захватываются. Этот тест требует доступной графической среды. Он не проверяет соединения через интернет, реальные устройства или системный выбор источника демонстрации.

Основные проверки также запускаются GitHub Actions на Windows и Linux.
